# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

AxisPilot (formerly Axis Selection) is a browser-only web app (React 19 + TypeScript + Vite, no backend; product data bundled as JSON). UI text is Korean with an English toggle (see `src/i18n/`). Mounting kits are matched by interface code and checked against their data sheet values (transferable torque, max. speed, inertia, no-load torque); the motor step's verdict includes the recommended kit's.

## Domain

The app sizes and selects a Festo Cartesian (linear) axis, plus the matching motor mounting kit and motor, from user-entered transport conditions.

**Inputs:** stroke, velocity, acceleration, jerk, payload mass, payload center of gravity (x/y/z offsets), mounting orientation — floor (horizontal), wall (horizontal, side-mounted), or vertical.

**Selection outputs, in order (each step depends on the previous):**
1. **Axis** — Festo ELGT, ELGD, EGC (incl. EGC-HD, ELGD-WD), ESBF (electric cylinder, ball screw)
2. **Motor** — Festo, Siemens, Mitsubishi; for Festo motors also the servo drive (CMMT-AS / CMMT-ST), motor cables and braking resistor
3. **Gearbox** — optional (direct drive or a compatible gearbox)
4. **Motor–axis mounting kit** — Festo, matched to the gearbox output when one is used
5. **Combination drawing** — the manufacturers' CAD models (STEP) assembled: 3D preview, STEP and DXF export

## Product data

The JSON files in `data/` are the source of truth and are edited by hand. The original Excel workbooks (Festo E-Drive selection Ver15.04, Motor Kit_Selection) and their export script are retired. Layout: one file per maker and product family, `data/<kind>/<maker>/<family>.json` with kind = `axes`, `motors`, `gearboxes`, `kits`, `drives`, `brakingResistors` or `cables`. Each file is `{ "items": [...] }`. `src/data/index.ts` loads every file with `import.meta.glob`, so new files need no code change. Discontinued families are left out there with `!` glob patterns while their files stay in `data/`: Mitsubishi HF-KP/HF-SP and Apex PA. **`data/README.md` lists every field with its unit.** Keep it in sync when adding fields.

Data gotchas:
- Units are mm, kg, N, Nm, kg·cm², m/s, rpm (per field in `data/README.md`).
- Motor `inertia` includes the brake for brake models; `inertiaWithoutBrake` excludes it.
- Gearbox `ratio` is i (5 = 5:1).
- Axis `speedLimitStroke`: for spindle axes, max speed is derated above this stroke.
- Mounting kits fit by **interface code**, not by part name. A kit matches when `axisCode` = the axis's `interfaceCode` and `motorCode` = the motor's `interfaceCode`, or the gearbox's (output side) when a gearbox sits in between. Part names often differ from the codes (`EAMM-A-T42-60P` is listed for `60PA`), and one kit has one item per code pair.
- `interfaceCode` is `null` for products whose code is unknown: about 290 motors (e.g. EMMS-AS, EMME, HK-*, HG-JR) and the Apex PA/AE gearboxes and AB/ABR sizes beyond the original Excel (AB142 and up, AB060A/AB090A, ABR). Fill it in from Festo's kit documentation; don't guess from similar products. Exception, confirmed by the user: HF-KP shares HG-KR's mounting dimensions and HF-SP shares HG-SR's, so HF-KP/HF-SP take the HG codes, and Apex `driveCode` comes from its `compatibleMotors` (all HF-KP/HF-SP). For the same reason Apex `compatibleMotors` lists the HG-KR/HG-SR code next to each HF code (`KP13` + `KR13`, `SP102` + `SR102`), so HG-KR/HG-SR get the same gearboxes.
- Festo motors come from the Festo data sheets (folder `Drive & Motor`): EMMT-AS/EC, EMMB-AS, EMMH-AS, EMMT-ST, EMMB-ST (closed loop) and EMMS-ST (open loop). EMCA, EMME-AS and EMMS-AS were removed (no data sheet). Families are series names (`EMMT-AS`, `EMMT-ST` …). Steppers carry `torqueCurve` (48 V); `controller` names the drive range. `orderCode`/`partNumber` are the base configuration's order type and part number (single-turn encoder, smooth shaft); the report's selection table lists them, plus the drive, cables and external braking resistor.
- CAD models sit in `data/<kind>/<maker>/Drawings/…/<partNumber>_<model>.stp` with a JSON of mating frames next to each (format in `data/README.md`). So far: every standard stroke of every Festo axis type except ELGT-TB-…-CS (not in the catalog; the app takes the nearest stroke and stretches it), the EMGA gearboxes (straight and -A- angle) and the priority-1 kits (standard EAMM-A/-U between a Festo axis and a Festo motor or EMGA), all with frame JSONs generated by `scripts/festo-cad/frames.mjs` (EAMM-A-T46-60P and EAMM-U-87-T46-60P-114 are the hand-made originals, which the script reproduces; parallel kits put the motor below the axis); the Festo motors in the data (no JSON needed: flange at z = 0, shaft +z, connector +y; EMMS-ST-28 models a lead reaching z = +156); Mitsubishi's motor files (every HG-KR/HG-SR/HG-JR, HK-MT and HK-RT motor in the data has one, HK-KT/ST except the 400 V class (…4W) and a few sizes; file names like `hg-kr13b_.stp`, matched without the data's `(200V)` suffix; flange at z = 0 like Festo, so no JSON). Only STEP is committed (the build writes them gzipped under their own names, `vite.config.ts` `gzipDrawings`, keeping the GitHub Pages site under 1 GB; `cad/stepText.ts` unpacks them after the fetch, the dev server serves them raw); the makers' DWG/DXF/IGES/ZIP downloads are git-ignored. The CADENAS files are CC BY-ND 4.0: the assembly copies them unchanged, but the axis length change edits the profile geometry.
- SA kits (`special: true`, custom-made in Korea) took their codes from the kit name, so they may not match standard motor codes. Three have axis codes that exist on no axis (`T46-60` ×2, `T42-80`).
- Kit transferable torque, inertia, max speed, mass, ratio (1) and the parallel kits' no-load torque come from the EAMM-A / EAMM-U data sheet tables; `dataSource` names the current-generation row (…-G2) when the kit's own name is not listed. Kits missing from the data sheets (the BF…/EB…/GD… inspection-window kits, older K… kits) keep `null`, and so do `efficiency` and `length`.

## Calculation reference (from the Excel)

The original E-Drive workbook (now retired) had four calc sheets — `BS_Horizontal`, `BS_Vertical`, `Belt_Horizontal`, `Belt_Vertical` — whose formulas the app's selection logic should reproduce. Wall mounting uses the "Horizontal [Sideways]" load case of the horizontal sheets. Key formulas (g = 9.81, η = drive efficiency — default 0.9 spindle / 0.8 belt, μ = friction — 0.05 spindle / 0.1 belt):

- **Travel per motor rev** dS: spindle `pitch / i`; belt `π · pulleyDiameter / i`.
- **Motion profile** (Excel is trapezoidal; jerk is a new input not in the Excel): `Tsa = v/a`, accel distance `v·Tsa/2`, constant-velocity distance `stroke − 2·accelDist`, cycle `tf = travel time + dwell`.
- **Inertia at motor** `JL = J_gear + J_brake + WL·(dS/(20π))² + (J_coupling + J_other + J_screw or z·J_pulley)/i²`, where WL = payload + slide mass; `J_screw = π·0.0078·(L/10)/32·(D/10)⁴` with L = stroke + 100.
- **Load torque** horizontal `TL = (Fc + μ(WL·g + FG))·dS / (2000π·η)`; vertical splits into unbalance `TU` and friction `TF` torques with separate up/down cases.
- **Accel/decel torque** `TMa = (JL/η + JM)·N0 / (9.55e4·Tsa) + TL`, `TMd = −(JL·η + JM)·N0 / (9.55e4·Tsa) + TL`; RMS torque over the cycle; check peak vs motor peak torque, RMS vs rated torque, `JL/JM` vs the motor's allowable inertia ratio, required speed vs rated speed.
- **Regeneration** `Pr = (ηm·Em − Ec)/tf` vs the motor's `regenPower`.
- **Festo criteria**: required force `Fc + FG + WL·a + μ·WL·g` (vertical: `+ WL·g`) ≤ `maxFeedForce`; required axis torque `F·dS/(2π·η·1000) + noLoadTorque` ≤ `maxDrivingTorque`; Festo inertia `J0 + JH·stroke/1000 + JL·payload + J_gear`.
- **Guide load**: forces/moments from payload COG offsets and inertial force `m·a`, combined `fv = Σ|F_i/F_max,i| < 1`; guide life `(1/fv)³ · 5000 km`.
- **Deflection**: simply supported beam with point load + self-weight using `Iy`/`Iz`, E = 70000 N/mm², vs `allowableDeflection`.
- **Ball screw life** (`Ball Screw 수명계산`): `L = (Ca / (fw·Fa))³ · 10⁶` rev, with load factor fw by speed (≤0.25 m/s: 1.2, ≤1: 1.5, ≤2: 2, >2: 3.5).

### Where the app deviates from the Excel (intentional)

- Load inertia uses Festo's catalog values `J0 + JH·stroke + JL·payload` instead of computing screw/pulley inertia from dimensions.
- Gearbox inertia and brake inertia are counted once on the motor side. The Excel adds them twice.
- Vertical guide moments use `m·(g + a)` once. The Excel's Mz counts gravity twice.
- Resistance is `Fc + μ·m·g + FG`. The Excel formula applies μ to FG as well.
- Jerk gives an S-curve profile. Torques, RMS and regeneration energy are integrated numerically over a full cycle: forward, back, then one dwell (the Excel has a dwell after each move).

## Architecture

- Two screens, switched at the top of the input column (`ModeSwitch`, above 사용 조건; `#gantry` in the address = gantry): 단축 선정 (one axis, with its parallel arrangement) and 조합축 선정 (XYZ / YZ / XY combination). `src/selection.ts` holds one axis's selection chain (`computeSelection(req, settings, picks)`: axis list, the picked or recommended axis, motors, gearbox options, kits), used by both screens; `ui/AxisSteps.tsx` renders the motion profile and steps 1–5 for one axis; `ui/useReportExport.ts` is the PDF export flow.
- `src/data/` loads every JSON file with `import.meta.glob` (`index.ts`) and defines the types (`types.ts`). `gearboxesFor` matches Apex compatibility codes (e.g. `KP053`) against motor model names. Festo EMGA items list motor series (`EMMT-AS-60`, …) from the ordering table in Festo's documentation, so they match the same way.
- `src/calc/` contains the pure, unit-tested selection logic in SI units. Inputs use mm and kg·cm², converted at the boundaries.
  - `motionProfile.ts`: move profiles are lists of `Phase`s with linearly varying acceleration (`Phase.load` = process force from pressing). `samplePhases` turns them into weighted samples (midpoint rule, plus zero-weight boundary points so peaks are exact).
  - `axisSelection.ts`: `evaluateAxis` builds the cycle (`cyclePhases`: forward, return, one dwell; `forwardPhases`/`backPhases` are one move with the dwell at its end, for the chart views) and computes per-sample torque at the axis drive shaft (`AxisSample.torque`, efficiency not applied). It runs the motor-independent checks (stroke, speed, accel, Fx, drive torque, guide fv, deflection) and life info. `mountingPosition: 'horizontal'` (ELGT-TB) adds `설치 방향`: vertical fails, wall warns. Ball screw axes take the speed limit from `speedCurve` (data sheet speed-stroke curve) at the built stroke, with a note when it is below `maxSpeed`; the old `스트로크별 속도 한계` warning (Excel `speedLimitStroke`) only remains for axes without a curve. ELGD-BS limits `이송력 Fx` the same way with `feedForceCurve` (screw buckling, force towards the motor); since the motor side is unknown, the larger force of both directions is checked. Ball screw life is the smaller of the load-based life and, for ESBF-BS, `maxSwitchingCycles` (10 million round trips) × 2 × stroke; under 5000 km (`SCREW_LIFE_MIN_KM`) the info item has `alert` and is shown in red, and a `볼스크류 수명` check warns. Electric cylinders (ESBF) carry data sheet curves instead of guide data: `압축력 (좌굴)` checks the largest pushing force (forward = rod extending) against `pressureForceCurve` at the stroke (`fail`), and `로드 횡하중 Fq` replaces the guide fv check, comparing the payload's lateral force with `rodLateralForceCurve` (`fail`). The ESBF 외부 가이드 사용 switch in the axis step (`Settings.externalGuide`) skips that check because the external guide carries the payload; its friction can go in 가이드 저항 FG. The moving mass adds `slideMassPer10mm` per stroke. Pressing mode (`Requirements.press`, 프레싱 in the 어플리케이션 선택 box between the input box and 상세 설정; default 일반; choosing 프레싱 sets the axis filters to 볼스크류 + ESBF and turns 외부 가이드 사용 on for floor/wall and off for vertical, also when the mounting changes while pressing; back to 일반 restores the default filters): the forward half becomes approach (stroke − press distance at the set velocity) → press move (press distance at press speed) → hold (standstill, `dir` +1), and the press move and hold carry the press force as `Phase.load`; the return has none. On a vertical axis the forward move goes up, or down when pressing top-down (`press.direction`, 압착 방향, shown for vertical + pressing; `verticalForward`): the weight then helps the press and the return lifts it. Chart, report and `moveLabel` name the moves 상승/하강 accordingly. So Fx, buckling, drive torque, peak/RMS torque and screw life see the press force only where it acts. `evaluateDrive` adds `가압 구간 토크` (torque of the press move at constant speed and the hold, forward efficiency applied, vs rated torque; warns like the constant-velocity torque, fails when conservative; shown whenever pressing), and `등속 구간 토크` covers only the travel moves (approach and return), leaving the press force out. Parallel arrangement (`Requirements.parallel`, 축 구성 box below 어플리케이션 선택; `parallelLayout`): members side by side along slide y, centred on y = 0: COG y is measured from the centre of the arrangement (two axes or axis + one guide at ∓spacing/2, the first axis at −; axis + two LM guides at −spacing, 0, +spacing, the axis in the middle or at −spacing), so a centred payload splits 50/50; the drawing is built from the first axis (`axisCog` shifts the COG to it). `twinMotor` (2축 · 모터 동기): each axis carries its lever-rule share of the payload (`layout.share`, the more loaded axis is checked; Fc, FG and the press force scale with it) and has its own motor, kit and drive (report quantity 2). `twinShaft` (2축 · 기구 동기): axis checks per axis likewise, but `samples`/`driveAt`/`inertia` are the motor train — both axes (inertia, no-load torque ×2), the whole payload and `shaftInertia`; `구동 토크 (연결축 포함)` warns when the total exceeds the axis drive torque. `guides` (축 + LM 가이드, 1 guide, or 2 with the axis in the middle or at the edge, `guideAxisEdge`): the axis drives the payload plus `guideMass` per guide. `memberLoads` spreads the guide loads over the members (rigid plate): the rolling moment becomes normal forces across the members (no Mx), My/Mz and in-plane forces are shared equally; with two axes the drives take the yaw of forces in the travel direction. Deflection uses the axis member's share; the LM guide loads (largest per guide) are info items for choosing the guides. The combination drawing adds the second axis of a twin arrangement at +spacing (`buildCombo`'s `twin`: with its own kit, gearbox and motor under motor sync; the connecting shaft and LM guides are not drawn).
 `selectAxes` filters and sorts by status, then axis mass. `axisOrder` gives the model and order number for the required stroke (ESBF, ELGT, ELGD, EGC; ELGT-TB is a customer solution `ELGT-TB-…-CS` with a part number for every stroke and no modular system): it rounds up to the next standard stroke (`strokePartNumbers`), otherwise it orders by `moduleNumber` (modular product system) with the stroke rounded up to a whole mm within `moduleStrokes.variable`, or to the next `moduleStrokes.fixed` stroke above it (ELGT-BS has fixed strokes only); the … in `typeCode` (or the ESBF `model`) takes the stroke, and mass/inertia use the ordered stroke. `AxisEvaluation.order` is what the UI and report show as the axis model.
  - `motorSelection.ts`: `evaluateDrive` reuses the axis samples. It applies gearbox ratio and efficiency (÷η when motoring, ×η when regenerating), adds rotor/gearbox/coupling inertia, and checks peak/RMS torque, speed, inertia ratio and regeneration, plus gearbox max output torque and max input speed (`maxInputSpeed`, EMGA and Apex AB/ABR; others skip with a note). Apex `maxTorque` is T2B = 1.8 × T2N. Steppers (`torqueCurve`) add `토크-회전수 선도`: the motor torque at each sample vs the 48 V curve at that speed (open loop ÷ `OPEN_LOOP_SAFETY` 1.5). `selectMotors` keeps one option per motor (its optional `attachKit` hook, given `attachParts` in selection.ts = `kitSelection.attachKit` then `controllerSelection.attachController`, adds the kit and the Festo drive package before the gearbox choice and the sort), by `Settings.useGearbox` (the 감속기 미사용 / 감속기 사용 switch in the motor step, between the maker and brake filters): off checks direct drive only; on checks each motor with its compatible gearboxes (`gearboxOptionsFor`, lowest ratio first) and keeps the lowest passing ratio (the lowest ratio when none passes), dropping motors without gearbox data.
  - `kitSelection.ts`: `findKits` matches kits by interface code (gearbox output code when a gearbox is used). SA kits are returned separately as reference. `evaluateKit` checks a kit for the selected axis and drive: `키트 전달 토크` (axis input torque + the kit's own inertia and no-load torque vs `transmissibleTorque`, fail) and `키트 최대 회전수` (axis shaft speed, fail); `모터 최대 토크 (키트 기준)` shows 주의 in the details when the motor (× gearbox) can exceed the kit torque (set a drive torque limit), but it is advice only: it stays out of the kit verdict (`MOTOR_MAX_LABEL`) and the rail's headline; and, with kit data, `최대 토크` / `실효 토크` / `관성비 (키트 포함)` re-run the motor checks with the kit's inertia and no-load torque (without a gearbox the kit inertia replaces `couplingInertia`); with a parallel kit, `이송력 Fx (병렬 키트)` checks the axis peak force against the ELGD's `maxFeedForceParallel` (fail). Axis data are kit-neutral: the old Excel `_parallel kit` axis entries were dropped, their only difference (lower Fx) lives in `maxFeedForceParallel`. Missing kit data gives `ok` with `키트 데이터 없음 — 확인 필요`. `attachKit` checks every matching kit for a drive (`DriveEvaluation.kits`), recommends the first one that does not fail, preferring kits with data sheet values (`kit`), keeps the drive's own verdict in `driveStatus` and folds the kit's into `status` (`warn` when no kit fits); App uses it for the motor list and the gearbox options, so the motor, gearbox and kit steps agree. The motor table has a 연결키트 column (verdict + recommended kit) and a 드라이브 column (selected CMMT); the kit step starts on the drive's recommended kit. The selected motor's details show `DrivePackage.tsx` (드라이브 · 케이블 · 제동저항: drive, cables, braking resistor with part numbers, the 모터 케이블 길이 input = `Settings.cableLength`, checks and notes); the report prints it on its own page after chapter 4, in the report's 11px text with part names 2pt larger. `KitNote`s list what to look at beyond that: no data sheet values, data from the -G2 model, IP65 -S1 derating, belt tension / counter bearing EAMG for parallel kits (EADT for EAMM-U-110/145), third-party motor shaft dimensions.
  - `controllerSelection.ts`: `selectController` builds the Festo drive package of a drive option (Festo motors only, `motor.controller`): the smallest CMMT drive of the motor's voltage class whose nominal/peak current covers the RMS/peak motor current (torque ÷ torque constant; open-loop steppers at nominal current) and whose peak duration covers the longest stretch above its nominal current, Festo's preferred drive (`preferredController`) shown when it differs; the cables for `Settings.cableLength` (`cables` items by role, motor regex, drive range and length; standard length → its part number; otherwise `configurable`: a variable-length part number or the modular product system's module number, with the length rounded up to its increment in the type; without it the next standard length; beyond the table `warn`); and the braking resistor: regenerative power at the motor shaft (losses and DC link absorption not deducted) against the integrated resistor's nominal power and pulse energy, else the first matching CACR whose rating covers it (CMMT-ST has none integrated: one is recommended above 1 Ws per braking). `attachController` folds its verdict into the option's `status` (`DriveEvaluation.controller`).
  - `gantry.ts`: the gantry. Axes are selected from the tool end (`gantryChain`: xyz = Z → Y → X, yz = Z → Y, xy = Y → X); each axis carries the `Stage` of the one before it (`stageOf`: selected axis + drive mass + everything it carries, as mass points from its mounting point, the moving part at the worst end: Z fully down, Y at the drive end, drive on the far end), and `gantryRequirements` turns that into the next axis's `Requirements` (payload = stage mass, COG in its slide frame, `cross` accelerations). World frame: X/Y horizontal, Z up (the 소재 무게 중심 input counts X and Z the other way: +X = world −X, in front of the Z slide; +Z = down; default z 50 below the slide); slide frames (`slideFrame`): floor faces up, wall X faces −Y, wall Y faces −X, Z faces −X. `Requirements.cross` (lateral/normal m/s²) adds inertial forces across the travel in `guideLoads`/`memberLoads` (forces split into travel/lateral/normal, `slideForces`; identical results without cross): axes below accelerate the whole system, axes above react with their moving part only (scaled by moving/carried mass); all taken as simultaneous. Z 프로파일 이동 (`Requirements.movingProfile`): the slide is clamped, the profile (axis mass − slide) and its drive move; the guide loads use the moving body's COG with the profile fully extended (`movingProfileCog`, payload COG measured from the profile's free end); ESBF is left out. `computeGantry` (selection.ts) runs the chain; a moving profile is evaluated twice so its drive mass is the selected motor + gearbox + kit. Motor mass comes from the data (`Motor.mass`, HK only) or `GantryInputs.motorMass`. Each axis has its own `Settings` (step filters); 상세 설정 and dwell are shared (`GantryInputPanel` writes them to all three). The X axis can use the parallel arrangements (`xParallel`); mounting offsets (`offsets.yz`, `offsets.xy`) place the carried axis on the carrier's slide (X: from the centre of its arrangement). `GantryWorkspace.tsx`: inputs, the axis tabs (`GantrySummary`; tabs, per-axis inputs and 축 설치 in X, Y, Z order (`gantryAxes`), each tab showing its place in the selection order, the header the order itself), the open axis's 하중 조건 and its `AxisSteps`; the rail and the PDF show the open axis (report chapter 1 adds a 조합축 section).
  - `types.ts`: `Requirements`, `Settings` with Excel-derived defaults, and the `Check`/`Status` model. A hard limit fails as `fail`. Deflection, rated-speed, regeneration and constant-velocity torque above the rated torque (`등속 구간 토크`; catches a long overloaded constant segment that a long dwell hides in the RMS) only `warn`; `Settings.conservative` (상세 설정 보수적 판정) makes the constant-velocity torque check `fail`. A missing data limit gives `ok` with a note.
- `src/cad/`: CAD assembly. `step.ts` reads/writes STEP Part 21 text (entity map, references, arguments); `structure.ts` finds product definitions, shape representations and solids. `stretch.ts` (`stretchPart`) changes a prismatic profile body's length in the text: points beyond a cut move along the axis, the cut sits where only axis-parallel lines cross it (edge extents from vertices, circle reach r·√(1−n_k²), arcs only where that extreme lies on them); shortening drops bounds and faces lying entirely in the removed window. A hole pattern (`patternOf`: bounds of the same shape across the axis repeating at one pitch, 3+ in a row; ELGT 100, EGC-HD 40/60) is kept: n whole pitches at a cut inside the pattern where the pitch before it repeats after it (`periodic`; lengthening fills the gap with copies of that pitch, `copyWindow`; shortening removes pattern only, so one-off features such as the ELGT-160 centring slot keep their place), the rest between the pattern and the moving end (n rounded, else floored/ceiled; no fit → the plain single cut). The spec is in file coordinates (turned into the part's own by its placement, `structure.ts` `placementOf`); `also` stretches further parts (ESBF piston rod), `move` shifts the placements of the parts at the moving end (end caps, the slide), and `stretchedOrigin` moves a drive or slide frame lying there (`buildCombo`). `assemble.ts` copies each part file with offset ids under a new top assembly (AP203 `CONFIG_CONTROL_DESIGN`, mm, NAUO + `ITEM_DEFINED_TRANSFORMATION` per part, ASCII-only names, the parts' licence lines in `FILE_DESCRIPTION`). `drawings.ts` lists the files (`import.meta.glob` `?url`, loaded on demand) and matches them to the selection; `combo.ts` (`buildCombo`) places axis → kit → (gearbox →) motor by `geometry.mate` of their frames, orients the axis by the mounting (world Z up; floor: travel +X, slide normal +Z; wall: normal −Y; vertical: motor on top, normal −Y; slide centre at the origin) and puts the COG at travel·x + (normal × travel)·y + normal·z. `occt.ts` tessellates the assembled STEP with occt-import-js (OpenCascade WASM, lazy) in a web worker (`occt.worker.ts` → `occtMesh.ts`; typed arrays transferred back, the 3D view's edge lines computed there too; on the calling thread where there is no `Worker`, as in tests) and tags meshes by part; `dxf.ts` draws front/top/right views (third-angle) from those meshes: B-rep face borders above 10° plus outlines (front/edge-on/back changes, so rounded profile corners and edge-on faces show), hidden parts removed with a CPU depth buffer (3×3 neighbourhood minimum), collinear pieces merged, overall dimensions, COG mark and title as DXF R12 (layers OUTLINE, DIM, COG, TEXT). `cad.test.ts` builds the real combination and reads it back with OpenCascade.
- `src/i18n/`: Korean/English. Korean source strings are the translation keys: components call `useT()` and write `t('스트로크')` or `t('적합 {pass}', { pass })`; `en.ts` holds the English. Calc labels and notes stay Korean (`Check.note` may have `{name}` placeholders filled from `noteArgs`) and are translated where shown, so lookups like `c.label === '관성비'` keep working. `translateData` handles the Korean words in product data (motor series/description). `i18n.test.ts` fails when a Korean string literal in `src/` has no English entry, or when Korean sits outside a string (JSX text) or in the static part of a template literal. Add the English to `en.ts` with any new UI text. The language toggle is in `RouteRail`; the choice is kept in localStorage and sets `<html lang>`. The PDF report follows the current language.
- `src/ui/` contains the React components. `App.tsx` holds the inputs (`req`, `settings`, language) and wraps `Workspace` (selection state, calculation, results, rail, report; auto-selects the first passing axis) in `ErrorBoundary`: a render or calculation error shows the inputs plus an error panel instead of a blank page, and editing an input retries. `InputPanel.tsx` is three boxes: 사용 조건 (acceleration entered as 가속도 or as 가속 시간 to reach the velocity; time mode converts with `accelerationForTime`, jerk included, so `Requirements.acceleration` stays the only calc input) + 소재 무게 중심 (with the 무게 중심 입력 가이드 image); 어플리케이션 선택 (일반 / 프레싱, with the press inputs and, on a vertical axis, 압착 방향); and a collapsible 상세 설정 box. Axis/motor filters (`Settings.families`, `makers`, …) are toggle buttons in each step's header. `RouteRail.tsx` is the sticky top rail: four route signs (selected part number, verdict, tightest check) that scroll to their step and highlight the step in view, plus PDF로 내보내기 and the English/한국어 switch (PDF export is blocked with a notice until axis, motor and kit are selected; `App.tsx` mounts `Report.tsx` off screen in `.report-stage`, `pdfExport.ts` renders each chapter to an image with `modern-screenshot` and lays them on A4 pages with `jspdf`, both lazy-loaded, then opens the PDF in a new tab. The calculation report: 1 입력 데이터·선정 모델 (the settings list ESBF 외부 가이드 only for an ESBF axis and leave out 보수적 판정), 2 모션 프로파일, 3 축, 4 모터 and, for Festo motors, a second 4 page 드라이브 · 케이블 · 제동저항, 5 감속기 (the selected gearbox only, with its own checks from `gearboxChecks`), 6 연결키트 (with the assembly orientation and its warnings); each chapter starts a new page). `MotionProfile` (chart + profile numbers; collapsing hides only the chart) sits above the steps, which render in order 축 → 모터 → 감속기 → 연결키트; step sections carry ids `step-axis`, `step-motor`, `step-gearbox`, `step-kit`, `step-drawing`. `DrawingStep.tsx` (step 5 조합 도면, after the kit) lists the drawing file found for each part (note when the axis length is adjusted or the motor file is another option), the 모터 조립 방향 (connector side, any kit) and, for a parallel kit, the 키트 조립 방향 (side the motor sits on), 상/하/좌/우 seen from the motor end of the axis with the slide surface up (`ComboOptions`, kept in `Workspace` as `assembly` because the report prints it; kit default 하, connector automatic until picked: the kit side with a parallel kit, 상 with an axial one, `connectorSide`; `buildCombo` turns the kit about the drive shaft and the motor about its shaft, `MotorMeta.connector` defaulting to `flange.up`, −y for Mitsubishi; `assemblyWarnings`: the connector faces the axis, and for 상 the motor on the slide side can shorten the usable stroke), and offers 3D 미리보기 (drawing files fetched once per page and cached, one retry on a network error; the open preview rebuilds 400 ms after the inputs settle; lazy `ComboViewer.tsx`, three.js with OrbitControls, Z up, view presets, part colours and the COG ball; follows the selection once opened), STEP 내보내기 and DXF 내보내기 (downloads); a combination is built once per selection and cached. With 감속기 미사용 the drive is direct (axis-kit-motor), step 3 only says so, and the kit is matched to the motor. With 감속기 사용, `App.tsx` evaluates every compatible gearbox for the selected motor and `GearboxStep.tsx` (step 3) lists them; the motor step's recommended gearbox is applied until the user picks another one there, and the kit is matched to the gearbox output. Changing the axis or motor goes back to the recommendation. `KitStep.tsx` (step 4) lists every kit for the selected axis and drive in one table (`orderKits`: axial before parallel, then without inspection window before with one), with columns 판정, 연결 방식 (직렬/병렬), 견시창 O/X, 모델명, 커플링 / 풀리 품번 and the 전달 토크 / 회전수 load bars; the selected kit shows its checks, data sheet values and 추가 검토사항. App keeps the selection and falls back to the first listed kit that does not fail. The rail's kit sign shows the kit verdict and its tightest check; the report's chapter 6 prints the same checks and notes. `ProfileChart.tsx` (`ProfilePlot` is the bare chart, reused by the report) plots the full cycle (왕복, default) or one move (forward or return), with the dwell always last (shaded `.chart-dwell`; press spans `.chart-press`). The view lives in `Workspace` and the PDF report prints the same view — position, velocity, acceleration, jerk and torque — from `tracePhases`, using `AxisEvaluation.driveAt` and `motorTorqueFn` for the torque (motor shaft when a motor is selected, else axis drive shaft).
