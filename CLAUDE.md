# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

Axis Selection is a browser-only web app (React 19 + TypeScript + Vite, no backend; product data bundled as JSON). UI text is Korean with an English toggle (see `src/i18n/`). Mounting kits are matched by interface code and checked against their data sheet values (transferable torque, max. speed, inertia, no-load torque) in the kit step; they do not change the axis and motor steps.

## Domain

The app sizes and selects a Festo Cartesian (linear) axis, plus the matching motor mounting kit and motor, from user-entered transport conditions.

**Inputs:** stroke, velocity, acceleration, jerk, payload mass, payload center of gravity (x/y/z offsets), mounting orientation — floor (horizontal), wall (horizontal, side-mounted), or vertical.

**Selection outputs, in order (each step depends on the previous):**
1. **Axis** — Festo ELGT, ELGD, EGC (incl. EGC-HD, ELGD-WD), ESBF (electric cylinder, ball screw)
2. **Motor** — Festo, Siemens, Mitsubishi
3. **Gearbox** — optional (direct drive or a compatible gearbox)
4. **Motor–axis mounting kit** — Festo, matched to the gearbox output when one is used

## Product data

The JSON files in `data/` are the source of truth and are edited by hand. The original Excel workbooks (Festo E-Drive selection Ver15.04, Motor Kit_Selection) and their export script are retired. Layout: one file per maker and product family, `data/<kind>/<maker>/<family>.json` with kind = `axes`, `motors`, `gearboxes` or `kits`. Each file is `{ "items": [...] }`. `src/data/index.ts` loads every file with `import.meta.glob`, so new files need no code change. Discontinued families are left out there with `!` glob patterns while their files stay in `data/`: Mitsubishi HF-KP/HF-SP and Apex PA. **`data/README.md` lists every field with its unit.** Keep it in sync when adding fields.

Data gotchas:
- Units are mm, kg, N, Nm, kg·cm², m/s, rpm (per field in `data/README.md`).
- Motor `inertia` includes the brake for brake models; `inertiaWithoutBrake` excludes it.
- Gearbox `ratio` is i (5 = 5:1).
- Axis `speedLimitStroke`: for spindle axes, max speed is derated above this stroke.
- Mounting kits fit by **interface code**, not by part name. A kit matches when `axisCode` = the axis's `interfaceCode` and `motorCode` = the motor's `interfaceCode`, or the gearbox's (output side) when a gearbox sits in between. Part names often differ from the codes (`EAMM-A-T42-60P` is listed for `60PA`), and one kit has one item per code pair.
- `interfaceCode` is `null` for products whose code is unknown: about 290 motors (e.g. EMMS-AS, EMME, HK-*, HG-JR) and the Apex PA/AE gearboxes and AB/ABR sizes beyond the original Excel (AB142 and up, AB060A/AB090A, ABR). Fill it in from Festo's kit documentation; don't guess from similar products. Exception, confirmed by the user: HF-KP shares HG-KR's mounting dimensions and HF-SP shares HG-SR's, so HF-KP/HF-SP take the HG codes, and Apex `driveCode` comes from its `compatibleMotors` (all HF-KP/HF-SP). For the same reason Apex `compatibleMotors` lists the HG-KR/HG-SR code next to each HF code (`KP13` + `KR13`, `SP102` + `SR102`), so HG-KR/HG-SR get the same gearboxes.
- SA kits (`special: true`, custom-made in Korea) took their codes from the kit name, so they may not match standard motor codes. Three have axis codes that exist on no axis (`T46-60` ×2, `T42-80`).
- Kit transferable torque, inertia, max speed, mass, ratio (1) and the parallel kits' no-load torque come from the EAMM-A / EAMM-U data sheet tables; `dataSource` names the current-generation row (…-G2) when the kit's own name is not listed. Kits missing from the data sheets (the BF…/EB…/GD… inspection-window kits, older K… kits) keep `null`, and so do `efficiency` and `length`.

## Calculation reference (from the Excel)

The original E-Drive workbook (now retired) had four calc sheets — `BS_Horizontal`, `BS_Vertical`, `Belt_Horizontal`, `Belt_Vertical` — whose formulas the app's selection logic should reproduce. Wall mounting uses the "Horizontal [Sideways]" load case of the horizontal sheets. Key formulas (g = 9.81, η = drive efficiency — default 0.9 spindle / 0.8 belt, μ = friction — 0.05 spindle / 0.1 belt):

- **Travel per motor rev** dS: spindle `pitch / i`; belt `π · pulleyDiameter / i`.
- **Motion profile** (Excel is trapezoidal; jerk is a new input not in the Excel): `Tsa = v/a`, accel distance `v·Tsa/2`, constant-velocity distance `stroke − 2·accelDist`, cycle `tf = travel time + dwell`.
- **Inertia at motor** `JL = J_gear + J_brake + WL·(dS/(20π))² + (J_coupling + J_other + J_screw or z·J_pulley)/i²`, where WL = payload + slide mass; `J_screw = π·0.0078·(L/10)/32·(D/10)⁴` with L = stroke + 100.
- **Load torque** horizontal `TL = (Fc + μ(WL·g + FG))·dS / (2000π·η)`; vertical splits into unbalance `TU` and friction `TF` torques with separate up/down cases.
- **Accel/decel torque** `TMa = (JL/η + JM)·N0 / (9.55e4·Tsa) + TL`, `TMd = −(JL·η + JM)·N0 / (9.55e4·Tsa) + TL`; RMS torque over the cycle; check peak vs motor peak torque, RMS vs rated torque, `JL/JM` vs the motor's allowable inertia ratio, required speed vs rated speed.
- **Regeneration** `Pr = (ηm·Em − Ec)/tf` vs the motor's `regenPower`.
- **Festo criteria**: required force `Fc + FG + WL·a + μ·WL·g` (vertical: `+ WL·g`) ≤ `maxFeedForce`; required axis torque `F·dS/(2π·η·1000) + noLoadTorque` ≤ `maxDrivingTorque`; Festo inertia `J0 + JH·stroke/1000 + JL·payload + J_gear`.
- **Guide load**: forces/moments from payload COG offsets and inertial force `m·a`, combined `fv = Σ|F_i/F_max,i| < 1`; guide life `(1/fv)³ · 5000 km`.
- **Deflection**: simply supported beam with point load + self-weight using `Iy`/`Iz`, E = 70000 N/mm², vs `allowableDeflection`.
- **Ball screw life** (`Ball Screw 수명계산`): `L = (Ca / (fw·Fa))³ · 10⁶` rev, with load factor fw by speed (≤0.25 m/s: 1.2, ≤1: 1.5, ≤2: 2, >2: 3.5).

### Where the app deviates from the Excel (intentional)

- Load inertia uses Festo's catalog values `J0 + JH·stroke + JL·payload` instead of computing screw/pulley inertia from dimensions.
- Gearbox inertia and brake inertia are counted once on the motor side. The Excel adds them twice.
- Vertical guide moments use `m·(g + a)` once. The Excel's Mz counts gravity twice.
- Resistance is `Fc + μ·m·g + FG`. The Excel formula applies μ to FG as well.
- Jerk gives an S-curve profile. Torques, RMS and regeneration energy are integrated numerically over a full cycle: forward, back, then one dwell (the Excel has a dwell after each move).

## Architecture

- `src/data/` loads every JSON file with `import.meta.glob` (`index.ts`) and defines the types (`types.ts`). `gearboxesFor` matches Apex compatibility codes (e.g. `KP053`) against motor model names. Festo EMGA items list motor series (`EMMT-AS-60`, …) from the ordering table in Festo's documentation, so they match the same way.
- `src/calc/` contains the pure, unit-tested selection logic in SI units. Inputs use mm and kg·cm², converted at the boundaries.
  - `motionProfile.ts`: move profiles are lists of `Phase`s with linearly varying acceleration (`Phase.load` = process force from pressing). `samplePhases` turns them into weighted samples (midpoint rule, plus zero-weight boundary points so peaks are exact).
  - `axisSelection.ts`: `evaluateAxis` builds the cycle (`cyclePhases`: forward, return, one dwell; `forwardPhases`/`backPhases` are one move with the dwell at its end, for the chart views) and computes per-sample torque at the axis drive shaft (`AxisSample.torque`, efficiency not applied). It runs the motor-independent checks (stroke, speed, accel, Fx, drive torque, guide fv, deflection) and life info. Ball screw axes take the speed limit from `speedCurve` (data sheet speed-stroke curve) at the built stroke, with a note when it is below `maxSpeed`; the old `스트로크별 속도 한계` warning (Excel `speedLimitStroke`) only remains for axes without a curve. ELGD-BS limits `이송력 Fx` the same way with `feedForceCurve` (screw buckling, force towards the motor); since the motor side is unknown, the larger force of both directions is checked. Ball screw life is the smaller of the load-based life and, for ESBF-BS, `maxSwitchingCycles` (10 million round trips) × 2 × stroke; under 5000 km (`SCREW_LIFE_MIN_KM`) the info item has `alert` and is shown in red, and a `볼스크류 수명` check warns. Electric cylinders (ESBF) carry data sheet curves instead of guide data: `압축력 (좌굴)` checks the largest pushing force (forward = rod extending) against `pressureForceCurve` at the stroke (`fail`), and `로드 횡하중 Fq` replaces the guide fv check, comparing the payload's lateral force with `rodLateralForceCurve` (`fail`). The ESBF 외부 가이드 사용 switch in the axis step (`Settings.externalGuide`) skips that check because the external guide carries the payload; its friction can go in 가이드 저항 FG. The moving mass adds `slideMassPer10mm` per stroke. Pressing mode (`Requirements.press`, 프레싱 in the 어플리케이션 선택 box between the input box and 상세 설정; default 일반; choosing 프레싱 sets the axis filters to 볼스크류 + ESBF and turns 외부 가이드 사용 on for floor/wall and off for vertical, also when the mounting changes while pressing; back to 일반 restores the default filters): the forward half becomes approach (stroke − press distance at the set velocity) → press move (press distance at press speed) → hold (standstill, `dir` +1), and the press move and hold carry the press force as `Phase.load`; the return has none. On a vertical axis the forward move goes up, or down when pressing top-down (`press.direction`, 압착 방향, shown for vertical + pressing; `verticalForward`): the weight then helps the press and the return lifts it. Chart, report and `moveLabel` name the moves 상승/하강 accordingly. So Fx, buckling, drive torque, peak/RMS torque and screw life see the press force only where it acts. `evaluateDrive` adds `가압 구간 토크` (torque of the press move at constant speed and the hold, forward efficiency applied, vs rated torque; warns like the constant-velocity torque, fails when conservative; shown whenever pressing), and `등속 구간 토크` covers only the travel moves (approach and return), leaving the press force out. `selectAxes` filters and sorts by status, then axis mass. `axisOrder` gives the model and order number for the required stroke (ESBF, ELGT-BS, ELGD, EGC; ELGT-TB has no order data and keeps its model name): it rounds up to the next standard stroke (`strokePartNumbers`), otherwise it orders by `moduleNumber` (modular product system) with the stroke rounded up to a whole mm within `moduleStrokes.variable`, or to the next `moduleStrokes.fixed` stroke above it (ELGT-BS has fixed strokes only); the … in `typeCode` (or the ESBF `model`) takes the stroke, and mass/inertia use the ordered stroke. `AxisEvaluation.order` is what the UI and report show as the axis model.
  - `motorSelection.ts`: `evaluateDrive` reuses the axis samples. It applies gearbox ratio and efficiency (÷η when motoring, ×η when regenerating), adds rotor/gearbox/coupling inertia, and checks peak/RMS torque, speed, inertia ratio and regeneration, plus gearbox max output torque and max input speed (`maxInputSpeed`, EMGA and Apex AB/ABR; others skip with a note). Apex `maxTorque` is T2B = 1.8 × T2N. `selectMotors` keeps one option per motor, by `Settings.useGearbox` (the 감속기 미사용 / 감속기 사용 switch in the motor step, between the maker and brake filters): off checks direct drive only; on checks each motor with its compatible gearboxes (`gearboxOptionsFor`, lowest ratio first) and keeps the lowest passing ratio (the lowest ratio when none passes), dropping motors without gearbox data.
  - `kitSelection.ts`: `findKits` matches kits by interface code (gearbox output code when a gearbox is used). `kitTypeFor` gives the axis's default kit type (parallel only for `_parallel kit` axes); `kitsOf` filters by type and 일반/견시창. SA kits are returned separately as reference. `evaluateKit` checks a kit for the selected axis and drive: `키트 전달 토크` (axis input torque + the kit's own inertia and no-load torque vs `transmissibleTorque`, fail) and `키트 최대 회전수` (axis shaft speed, fail); `모터 최대 토크 (키트 기준)` warns when the motor (× gearbox) can exceed the kit torque (set a drive torque limit); and, with kit data, `최대 토크` / `실효 토크` / `관성비 (키트 포함)` re-run the motor checks with the kit's inertia and no-load torque (not added again for `_parallel kit` axes, whose data include them; without a gearbox the kit inertia replaces `couplingInertia`). Missing kit data gives `ok` with `키트 데이터 없음 — 확인 필요`. `KitNote`s list what to look at beyond that: no data sheet values, data from the -G2 model, IP65 -S1 derating, belt tension / counter bearing EAMG for parallel kits (EADT for EAMM-U-110/145), third-party motor shaft dimensions.
  - `types.ts`: `Requirements`, `Settings` with Excel-derived defaults, and the `Check`/`Status` model. A hard limit fails as `fail`. Deflection, rated-speed, regeneration and constant-velocity torque above the rated torque (`등속 구간 토크`; catches a long overloaded constant segment that a long dwell hides in the RMS) only `warn`; `Settings.conservative` (상세 설정 보수적 판정) makes the constant-velocity torque check `fail`. A missing data limit gives `ok` with a note.
- `src/i18n/`: Korean/English. Korean source strings are the translation keys: components call `useT()` and write `t('스트로크')` or `t('적합 {pass}', { pass })`; `en.ts` holds the English. Calc labels and notes stay Korean (`Check.note` may have `{name}` placeholders filled from `noteArgs`) and are translated where shown, so lookups like `c.label === '관성비'` keep working. `translateData` handles the Korean words in product data (motor series/description). `i18n.test.ts` fails when a Korean string literal in `src/` has no English entry, or when Korean sits outside a string (JSX text) or in the static part of a template literal. Add the English to `en.ts` with any new UI text. The language toggle is in `RouteRail`; the choice is kept in localStorage and sets `<html lang>`. The PDF report follows the current language.
- `src/ui/` contains the React components. `App.tsx` holds the inputs (`req`, `settings`, language) and wraps `Workspace` (selection state, calculation, results, rail, report; auto-selects the first passing axis) in `ErrorBoundary`: a render or calculation error shows the inputs plus an error panel instead of a blank page, and editing an input retries. `InputPanel.tsx` is three boxes: 사용 조건 (acceleration entered as 가속도 or as 가속 시간 to reach the velocity; time mode converts with `accelerationForTime`, jerk included, so `Requirements.acceleration` stays the only calc input) + 소재 무게 중심 (with the 무게 중심 입력 가이드 image); 어플리케이션 선택 (일반 / 프레싱, with the press inputs and, on a vertical axis, 압착 방향); and a collapsible 상세 설정 box. Axis/motor filters (`Settings.families`, `makers`, …) are toggle buttons in each step's header. `RouteRail.tsx` is the sticky top rail: four route signs (selected part number, verdict, tightest check) that scroll to their step and highlight the step in view, plus PDF로 내보내기 and the English/한국어 switch (PDF export is blocked with a notice until axis, motor and kit are selected; `App.tsx` mounts `Report.tsx` off screen in `.report-stage`, `pdfExport.ts` renders each chapter to an image with `modern-screenshot` and lays them on A4 pages with `jspdf`, both lazy-loaded, then opens the PDF in a new tab. The calculation report: 1 입력 데이터·선정 모델, 2 모션 프로파일, 3 축, 4 모터, 5 감속기, 6 연결키트, each chapter starts a new page). `MotionProfile` (chart + profile numbers; collapsing hides only the chart) sits above the steps, which render in order 축 → 모터 → 감속기 → 연결키트; step sections carry ids `step-axis`, `step-motor`, `step-gearbox`, `step-kit`. With 감속기 미사용 the drive is direct (axis-kit-motor), step 3 only says so, and the kit is matched to the motor. With 감속기 사용, `App.tsx` evaluates every compatible gearbox for the selected motor and `GearboxStep.tsx` (step 3) lists them; the motor step's recommended gearbox is applied until the user picks another one there, and the kit is matched to the gearbox output. Changing the axis or motor goes back to the recommendation. `KitStep.tsx` (step 4) lists every kit for the selected axis and drive in one table (`orderKits`: the axis's kit type first, then without inspection window before with one), with 판정 and 연결 방식 (직렬/병렬) first, 견시창 O/X and the 전달 토크 / 회전수 load bars; the selected kit shows its checks, data sheet values and 추가 검토사항. App keeps the selection and falls back to the first listed kit that does not fail. The rail's kit sign shows the kit verdict and its tightest check; the report's chapter 6 prints the same checks and notes. `ProfileChart.tsx` (`ProfilePlot` is the bare chart, reused by the report) plots the full cycle (왕복, default) or one move (forward or return), with the dwell always last (shaded `.chart-dwell`; press spans `.chart-press`). The view lives in `Workspace` and the PDF report prints the same view — position, velocity, acceleration, jerk and torque — from `tracePhases`, using `AxisEvaluation.driveAt` and `motorTorqueFn` for the torque (motor shaft when a motor is selected, else axis drive shaft).
